CapySlides tools

Every command and helper of CapySlides in one place. Commands run from this repository (the CapySlides folder) and work on any presentation folder; a presentation folder itself never needs the repository. Details: README.md (overview, quick start, troubleshooting), AUTHORING.md (how to write slides) and SPEC.md (design decisions).

Typical workflow

new.py creates the folder
Edit the deck (open it with ?dev)
image_sizes.py after adding images
check.py after every change
pack.py makes the zip to submit

All projects live in presentations/ (each folder is self-contained and can be zipped on its own; everything inside it is in .gitignore, so projects are never committed). Example talks published with showcase.py (in showcase/) will follow. Old presentation and a newer template? update.py brings it to the newest engine first. Another animation later? add_animation.py creates and registers it.

Command-line tools

tools/new.py start a presentation

Creates a self-contained project in presentations/<name>. Asks for the project name, file prefix, title, subtitle, presenter, course title/type, semester and — one prompt per animation, empty answer = done — animation names. Empty answers keep the template placeholders.

python tools/new.py MyTalk          # → presentations\MyTalk\  (name asked if omitted)

Creates MyTalk_presentation.html, one <name>_animations.html per animation (already registered in DECK.animations), images/eth_zurich_main_building.jpg, and the AI helpers CLAUDE.md + AUTHORING.md. Answers can be piped in, one per line.

tools/add_animation.py another animation for an existing presentation

Creates <Name>_animations.html from the current starter animation (panel system included) and registers it in DECK.animations, after the existing entries. Only that list in the deck changes (backup .bak). Prints the <section data-type="animation"> line to show it as a slide.

python tools/add_animation.py "presentations\MyTalk" "Model Scaling"   # name asked if omitted

Pass the deck file instead of the folder if the folder holds several decks. Refuses an existing file or id.

tools/check.py after every change

Opens the deck headless in Chrome/Edge (offline) and lists everything the ?dev view would show, per slide and step: missing images/animations, invalid step attributes, formula errors, files outside the folder, … Also reports <img> tags with missing/wrong width/height, images an animation file cannot load, and outdated engine versions.

python tools/check.py "presentations\MyTalk"          # folder or deck file
python tools/check.py "presentations\MyTalk" --json   # machine-readable

Exit code 0 = nothing to fix, 1 = problems, 2 = wrong arguments.

tools/image_sizes.py after adding or changing images

Writes each image's natural pixel size into its <img> tag, so a missing image still keeps its place and shape. Writes a .bak backup.

python tools/image_sizes.py "presentations\MyTalk\MyTalk_presentation.html"
python tools/image_sizes.py "…_presentation.html" --check   # report only, exit 1 if wrong

tools/update.py older presentation, newer template

Replaces only the generated engine blocks (deck: DECK-ENGINE; animations: ANIM-VENDOR, ANIM-CONTRACT), verifies that nothing else changed (a file saved with Windows line endings keeps them), writes .bak backups and refreshes CLAUDE.md / AUTHORING.md (also the paths in it, e.g. after the repository folder was moved or renamed). Refuses to downgrade.

python tools/update.py "presentations\MyTalk"
python tools/update.py "presentations\MyTalk" --dry-run   # only report
python tools/update.py "presentations\MyTalk" --force     # allow a downgrade

tools/pack.py submit

Writes <prefix>.zip next to the folder, e.g. presentations\MyTalk.zip (or into --out) with only what the presentation uses: the deck, every file it names (the animation files in DECK.animations, images, linked files) and every file those name in turn (an animation's images), plus what the engine uses by default (the cover image when DECK.cover names none). Never included: CLAUDE.md, AUTHORING.md, *.bak, zips and hidden files. Files nothing uses are listed as left out. A file that code only builds by name ('images/frame' + i + '.png') must be written out once, e.g. in an array. Before zipping, a copy is checked in a temporary folder outside the repository, so the zip is proven to work on its own and offline. It reports its four steps as it goes: each starts with [STEP 1/4] Finding the files …, everything it does is indented below that line, and it ends with PASSED: … or FAILED: ….

python tools/pack.py "presentations\MyTalk"
python tools/pack.py "presentations\MyTalk" --out "D:\Submissions"
python tools/pack.py "presentations\MyTalk" --force   # zip even with problems

tools/showcase.py publish a talk as an example (GitHub Pages)

Copies what the presentation uses (the same selection as pack.py: no CLAUDE.md, AUTHORING.md or unused files) to showcase/<name>/. The copy is checked offline in a temporary folder first; if the check finds problems, nothing is replaced (unless --force). A screenshot of one slide becomes the preview image (--preview: slide id or 0-based index, optionally :step; remembered for the next run; default: the title slide). Then showcase/index.html is rewritten with one card per talk (title, paper, course, number of slides, preview, link to the GitHub repository).

python tools/showcase.py "presentations\MyTalk" --preview results   # publish a talk
python tools/showcase.py "showcase\MyTalk"                           # refresh it after editing the copy
python tools/showcase.py "presentations\MyTalk" --replace            # overwrite the copy from the project
python tools/showcase.py "presentations\A" "presentations\B"          # several at once
python tools/showcase.py                                              # only rewrite index.html

The showcase copy is public and maintained in place: it may differ from your project on purpose (only material you may publish, e.g. charts redrawn instead of paper figures), so publishing over an existing copy from another folder is refused unless --replace is given. Remove a talk: delete its folder in showcase/ and run the tool without arguments. On every push that changes showcase/, .github/workflows/showcase.yml publishes it as the repository's website (one-time setup on GitHub: Settings → Pages → Source: GitHub Actions). update.py also works on a showcase copy (it gets no CLAUDE.md / AUTHORING.md).

Repository development

tools/build.py after changing engine/

Generates template/ and AUTHORING.md from the engine sources. --check exits 1 if anything generated is stale.

python tools/build.py
python tools/build.py --check

tools/fetch_vendor.py changing a font or KaTeX version

Downloads the pinned fonts and KaTeX listed in engine/vendor/manifest.json and writes the hash lock; --verify checks the vendored files offline.

python tools/fetch_vendor.py
python tools/fetch_vendor.py --verify

Tests after every engine or tool change

Build and engine tests; the engine tests run fixture decks in headless Chrome/Edge (skipped without a browser).

python -m unittest discover tools/tests
